# 08 屋外実機テスト

## 目的と開始条件

実空で「計算方向と端末照準が一致する」こと、磁気干渉時に誤発見しないことを確認する。安全確認、数学・合成センサーテスト、日英表示、VoiceOver の基本確認を先に通し、Xcode の開発署名で試験用 iPhone へ入れる。Codemagic や配布用 IPA はまだ作らない。

## 高度と方位品質

| 条件 | 期待動作 | 合否への扱い |
|---|---|---|
| 幾何高度 `<0°` | 自動で練習へ切替 | ライブ成功数に入れない |
| `0°以上2°未満` | 低高度警告。ライブ案内は可、発見不可 | 境界動作だけ確認 |
| `2°以上5°未満` | 低高度警告。good/fair なら発見可 | 地形・大気差の不確実帯として探索成功率から除外し、参考記録にする |
| `5°以上` | 通常のライブ候補 | 成功率の評価対象。主要試験は高度15°以上を選ぶ |
| good `<=8°` / fair `>8°..<=10°` | 適応許容角3〜6°、0.8秒保持で発見可 | 有効試行 |
| needsCalibration `>10°..<=25°` | 粗い案内だけ、発見不可 | 補正遷移を確認 |
| unavailable `無効/>25°` | 全案内停止、発見不可 | 停止と説明を確認 |

「0〜5°」は境界を含めてサンプルを採るが、実装上の警告域は `0°以上5°未満` とする。5°ちょうどで警告が解除される境界も確認する。

## 手順

1. 開けた安全な場所で立ち止まり、車、磁石、金属柵、鉄骨、送電設備から離れる。日時、粗い地域、機種、OS、対象星、幾何高度を記録する。
2. good/fair の有効方位精度、角距離、成否、所要時間を記録する。許容角は `T = clamp(3 + 有効方位精度/3, 3, 6)` 度で、0.8秒未満の横切りを成功にしない。
3. 別日2セッション以上、2星×各4回以上（計8回以上）を最低ゲートとし、高度15°以上で60秒以内の発見が6/8回以上であることを確認する。
4. 実星から20°以上外して8回以上保持し、誤発見0回を確認する。
5. 可能なら2機種・2夜・各星10回へ拡張し、中央値、90パーセンタイル、good/fair 到達率、除外率を記録する。低高度帯の結果は通常帯と混ぜない。
6. 車内、磁石付近、鉄骨付近では静止したまま状態遷移だけを確認する。危険な場所へ歩かせず、精度が悪化しない干渉も「検出できなかった」と記録する。

## 通過条件

- [MVP要件とデータ権利判断](REQUIREMENTS-AND-RIGHTS.md)の A-FIELD 全件を満たし、失敗を精度、遮蔽物、UI、計算、操作へ分類済み。
- good/fair だけが発見し、needsCalibration/unavailable、移動中、古いセンサー値では発見しない。
- 高度境界と低高度警告が上表どおりで、練習結果を実空の発見として表示しない。
- 個人位置を外部送信せず、公開記録では場所を丸める。

通過するまで星数・星座・カメラ補助を増やさず、Codemagic 設定、配布用 IPA、ストア素材を作らない。
